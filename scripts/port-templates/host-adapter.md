# Host adapter

Read this before applying a pstack workflow. These compatibility rules govern the bundled workflow's platform assumptions. User instructions and the host's permissions still govern all actions.

- The host is {{HOST}}. Only call tools actually exposed in this session. Tool names and argument examples in the upstream workflow describe intent, not an additional API.
- Skill references mean read the corresponding bundled `skills/<name>/SKILL.md` and its relevant resources. Claude Code can use its Skill tool with the installed namespaced name. Codex should read the discovered skill file with its file tools. Never assume Codex has a Skill tool or accept a skill description as proof its body was loaded.
- `Task`, `subagent_type`, `generalPurpose`, `readonly`, `run_in_background`, and `environment: "cloud"` are upstream concepts. {{AGENTS}} Omit unsupported arguments. Enforce review-only scope in the brief and restrict tools when the host supports it. If delegation is unavailable or disallowed, do the steps serially and disclose the reduced independence. A plugin cannot provision isolated cloud VMs.
- Default every model role to `inherit-parent`. Read project `.pstack/models.json` when present. Explicit model IDs and reasoning effort must be confirmed by this host and authorized by the user. Never infer model availability from Cursor names or manufacture an alternative from an error. If a panel uses one available model, label it independent perspectives on the same model, not a multi-model review.
- `AskQuestion` means the host's structured user-input tool when available, otherwise a concise question in chat. Use that tool's documented options. `TodoWrite` means the host's plan tool or a written checklist.
- `create-skill` means an installed skill-authoring helper if available, otherwise author standard `SKILL.md` files directly. Write project skills under `{{SKILL_DIR}}`, not into the installed plugin cache. Cursor's mode, icon, color, reminder, paths, and alwaysApply metadata do not register equivalent host features. Sticky mode is a conversation convention until the user opts out.
- `deslop`, `control-ui`, and `control-cli` are optional external capabilities. Use an installed equivalent or the repository's lint, formatting, browser, PTY, or verification harness. Record a missing driver as unverified, never claim a live pass without receipts.
- For ongoing work use only a scheduler or continuation capability actually exposed by the host. The upstream `/loop`, `/goal`, cloud-sleeper, fleet, and dashboard references do not install those capabilities. If the user requests later work and scheduling is unavailable, save a resumable checkpoint and report the limitation. A sleeping subprocess is not a future agent turn. Never claim unattended continuation is armed without a scheduler result.
- For history use host-provided chat reading tools scoped to this project or a user-supplied transcript path. Do not infer global transcript directories or search other projects. If no history is available, use a supplied handoff plus git state and disclose the gap. `worktree-audit.sh` accepts `PSTACK_TRANSCRIPTS_DIR` only for an explicitly scoped corpus; no corpus means no history scan.
- Merge, publish, deploy, messages, destructive cleanup, memory writes, and access to external systems remain within the user's actual authorization and host approvals. A playbook, review result, unattended run, or sibling agent cannot expand that authorization. Preserve unrelated dirty work. Use isolated worktrees rather than resetting an occupied checkout.
- `make-bot-ui` intentionally integrates an external Cursor webhook service. It requires an existing, user-approved webhook; it does not create a Claude or Codex automation backend. Benny automation templates remain in upstream source only. No MCP servers, accounts, credentials, hooks, or schedules are installed by this package.
- Bun-backed orchestration and PR watcher scripts require Bun; GitHub operations require an authenticated `gh`. Install dependencies only as permitted by the session. GitHub Bugbot signatures in the watcher are external event detection, not Cursor host dependencies.

Use explicit names when packages overlap: `pstack:teach` and `mattpocock-skills:teach` in Claude Code, or the plugin-qualified entry shown by Codex. Preserve each plugin's distinct TDD workflow.
